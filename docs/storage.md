# 저장 방식 — DB 없이 폴더와 파일로 (2026-10-28 확정)

**이 프로젝트는 DB 를 쓰지 않는다.** 노트는 그냥 디렉토리와 `.md` 파일, 나머지는 JSON 파일이다.
예전 SQLite(`instance/marknote.db`)는 내용이 거의 없어 옮기지 않는다 (앱은 더 이상 읽지 않음).

## 폴더 구조
```
instance/
  notes/                       ← 노트 (탐색기·VS Code·옵시디언으로 열어도 그대로)
    회사/                      ← 프로젝트 = 맨 위 폴더
      README.md                ← 폴더 설명 (있으면 폴더 화면 위에 보임, 노트 목록에는 안 나옴)
      회의록.md                ← 노트
      2026-03/                 ← 폴더 안 폴더 (깊이 제한 없음)
        3월 회의.md
    분류 안 됨/                ← 원래 폴더가 없어진 채 복원한 노트, 낱개 .md 가져오기
    .archive/<n>/<원래 경로>   ← 보관함 (n = 옮길 때마다 새 칸)
    .trash/<n>/<원래 경로>     ← 휴지통
    .marknote/index.json       ← 앱 전용: 순서, 보관·휴지통 칸의 원래 위치, 앱 안쪽 번호
  uploads/<uuid>.<확장자>      ← 그림 (/files/<uuid>)
  decks/<번호>.json            ← 프레젠테이션 (슬라이드 포함 한 파일)
  ai-chats/<대화>.jsonl        ← AI 대화 기록
  ai-edits/notes|decks/<번호>.json ← AI 수정 기록 (되돌리기·확정용)
  settings.json                ← 설정 화면 값, 로그인 세대(모든 기기 로그아웃)
  ai-usage.json                ← 날짜별 AI 사용량
```

## 규칙
- **맨 위(`notes/` 바로 아래)에는 폴더(= 프로젝트)만.** 거기 놓인 `.md` 파일은 무시
- **폴더 안에는 폴더와 노트(.md).** 노트 아래에 노트는 없다 — 묶고 싶으면 폴더
- **제목 = 파일·폴더 이름** (노트는 `.md` 제외). 못 쓰는 글자(`\ / : * ? " < > |`)는 빠진다
- 같은 폴더 안에 같은 이름 금지 (대소문자·공백 무시). 단 폴더 `회의` 와 노트 `회의.md` 는 서로 다른 이름이라 함께 둘 수 있다 (같은 종류끼리만 비교)
- **노트 파일은 순수 본문만.** 아이콘·앞머리(`---`) 없음. 화면은 폴더 📁 / 노트 📄 고정
- `README.md` = 그 폴더의 설명. 폴더 화면에서 "설명 편집"으로 고친다
- `images` 라는 폴더 이름은 내보내기 그림 폴더라 쓰지 않는다

## 순서
- 직접 정한 순서 (사이드바·폴더 목록에서 끌어서 바꿈) → `index.json` 에 저장
- 폴더가 노트보다 먼저. 앱 밖에서 새로 생긴 파일은 맨 뒤 (그 안에서는 이름순)

## 주소
- 화면 주소 = 파일 경로: `/n/회사/회의록.md`, 폴더는 `/n/회사/2026-03/`
- 이름을 바꾸거나 옮기면 주소도 바뀐다 (예전 주소는 열리지 않음)
- 앱·AI 안쪽에서는 번호(index.json)를 계속 쓴다 — 화면·파일에는 나오지 않음.
  열려 있는 편집기, AI 되돌리기, 채팅의 "다루는 노트"가 이름이 바뀐 뒤에도 같은 노트를 가리키게

## 노트끼리 링크
- 보통 마크다운 상대 경로: `[회의록](../회의록.md)`, 폴더는 `[2026-03](2026-03/)` → VS Code·GitHub 에서도 그대로 동작
- 화면에서는 그 노트의 주소(`/n/...`)로 열린다. 없는 파일을 가리키면 끊어진 링크로 표시
- **앱에서 이름을 바꾸거나 옮기면 그 노트를 가리키는 링크를 모든 노트에서 함께 고친다** (옮긴 노트 안의 링크도 새 위치 기준으로)
- 앱 밖에서 이름을 바꾸면 링크는 끊어진 채로 남는다
- 그림은 `/files/<uuid>` (앱 업로드)

## 블록 편집기
- 블록 = 본문을 빈 줄로 나눈 조각. 블록 번호는 **서버 메모리**에만 있다 (파일엔 없음)
- 저장할 때마다 파일 전체를 다시 쓴다 (임시 파일에 쓴 뒤 바꿔치기 — 중간에 꺼져도 파일이 깨지지 않음)
- 앱 밖에서 파일이 바뀌었는데 편집기가 예전 블록 번호로 저장하면 409 → "다시 불러오기"

## 보관함 · 휴지통
- 폴더째 또는 노트 하나를 `.archive/<n>/` · `.trash/<n>/` 로 원래 경로 그대로 옮긴다
- 복원: 원래 폴더가 있으면 그 안으로. 없으면 폴더는 맨 위(프로젝트)로, 노트는 "분류 안 됨"으로. 같은 이름이 생겼으면 "(2)"
- 영구 삭제하면 그 노트들 본문에 있던 그림 파일도 지운다

## AI (이전과 같음 + 폴더 이해)
- **AI 사용 방식은 그대로**: 구독 로그인 Claude Code, F2 채팅, 모델·사용량, 대화 기록, 비공개 표시, 바로 수정 + `되돌리기 | 확정`(Ctrl+Z / Ctrl+S)
- **AI 는 파일을 직접 열지 않는다.** Claude Code 파일 도구는 계속 끔(`--tools ""`) → `{{ }}`·`:::비공개` 를 가리기 위해 MarkNote 도구로만 읽고 씀
- 도구 결과마다 `kind`(folder/note)와 `file`(예: `회사/회의록.md`, 폴더는 `회사/2026-03/`)
- **"OO 프로젝트 확인해줘" → 그 프로젝트(폴더) 안의 노트를 전부 읽는다**
  - 채팅에서 프로젝트·폴더 이름을 부르면 서버가 그 안 노트 전부(README 포함, 하위 폴더까지)를 함께 보냄
  - `read_page` 로 폴더를 읽어도 안의 노트 전부 (길면 앞에서부터, 넘친 노트는 목록만 → 하나씩 `read_page`)
- `create_page` 는 폴더 안에만 노트를 만든다. `folder=true` 면 폴더. 맨 위에는 폴더(프로젝트)만
- 폴더에는 내용을 쓸 수 없다 — 설명은 그 폴더의 `README.md` 노트를 고친다
- **삭제 = 휴지통으로 이동** (`trash_page`, 설정 "노트 삭제 (휴지통으로)" — 기본 켜짐): 파일을 `.trash/<n>/<원래 경로>` 로 옮길 뿐 지우지 않는다.
  `되돌리기` = 원래 자리로 복원, `확정` 해도 휴지통에 남음. **영구 삭제·휴지통 비우기는 AI 가 할 수 없다** (사용자만)
- 질문마다 지금 노트·다루는 노트를 **파일에서 새로 읽어** 보낸다 → 앱 밖에서 고친 내용도 반영
- 페이지 강조는 파일 내용이 AI 가 쓴 그대로일 때만 (직접 고쳐 저장하면 저절로 사라짐)
- 되돌리기는 블록 내용 기준 3-way 비교 (그 뒤 다른 곳을 고쳤어도 AI 가 바꾼 부분만 되돌림)
- 대화 기록은 파일 (SQLite 이전 계획은 취소 → 많이 쌓이면 `ai-chats/archive/` 로 정리만)
- MCP 서버는 따로 뜨는 프로세스라 공유 파일(`index.json`, `ai-edits/`)은 잠금 파일 + 바꿔치기 쓰기

## 가져오기 · 내보내기
- 내보내기 zip = 폴더 구조 그대로 (+ `images/`). 링크는 상대 경로라 그대로 동작
- 가져오기: 폴더 → 폴더, `.md` → 노트, `README.md` → 설명. 노션 zip 의 `X.md` + `X/` 짝은 폴더 `X` + 그 안 `README.md` 로
- 맨 위에 낱개 `.md` 를 가져오면 "분류 안 됨" 프로젝트로
